WINDOWS IT SUPPORT HANDBOOK - OFFLINE EDITION

1. Extract this ZIP to a folder.
2. Double-click Windows-Support-Guide.html to open it in a browser.
   This file is self-contained and can be shared on its own.
3. Use the category/subcategory menu, search or reference-view filter.
4. PowerShell: follow the approved one-time policy setup in the guide,
   then paste the complete PowerShell menu setup into Windows PowerShell.
   CMD: click Copy one-line CMD starter, paste into Command Prompt and
   press Enter. Open the selected shell as Administrator for admin tasks.
5. Read commands and prompts before running. Changes are selected tasks;
   no run-all repair, GUI launches or automatic reboot is included.

The PowerShell starter is restored from your original uploaded starter;
its original SHA-256 is preserved. It writes a versioned script under
LOCALAPPDATA\WindowsSupport\Releases. PowerShell logs and selected backups
are also stored under LOCALAPPDATA\WindowsSupport. Do not use the manual's
sensitive OEM-key retrieval commands in a logged support session.

Execution policy and managed organization controls remain in force. If
script execution is blocked, follow the organization's approved process.
The native CMD starter uses PowerShell inline for initial local decoding;
the resulting menu runs in CMD. Neither starter downloads executable code.

WINDOWS SANDBOX (Windows edition/hardware must support it)
From the extracted root folder in Windows PowerShell:
  .\tests\StartWindowsSandbox.ps1
Networking and clipboard redirection are disabled. Source files are mapped
read-only. Results are saved under LOCALAPPDATA\WindowsSupport\SandboxResults.
The automatic runner tests parsing/mocked control flow and selected real
read-only diagnostics. It does NOT automatically test every command or
apply repairs. Run feature, install, account, registry and firewall changes
only in a separately reviewed disposable Windows lab.
